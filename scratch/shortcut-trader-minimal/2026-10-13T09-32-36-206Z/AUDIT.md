# Минимальная оптимизация user_shortcut_trader.js

## Контракт
Только оптимизация существующей отрисовки. Без добавления функций/кнопок и без изменения интерфейса, торговой логики, интервалов, настроек и серверных сообщений.
Целевой файл: C:\OSPanel\home\tso_client\userscripts\user_shortcut_trader.js.
Копия в tso_portable НЕ заменялась.

## Изменения
1. renderBody: HTML каждой строки формируется прежней renderTradeRow, в прежнем порядке и с прежними индексами. Вместо append каждой строки в живой DOM строки собираются в массив и вставляются одной операцией append(rows.join('')). Пустой список по-прежнему оставляет пустой контейнер.
2. При совместном обновлении информации о слотах и счётчика выбора доступное количество слотов читается один раз и передаётся обеим функциям. Их прежние вызовы без аргумента продолжают самостоятельно получать данные. В режиме друзей чтение слотов по-прежнему не выполняется. Значение 0 не подменяется новым чтением.

Размер диффа: 16 добавленных / 11 удалённых строк.
Меню, modal lifecycle, picker, GameDataSource, settings, ActionsService, TradeService.send, TimedQueue, LocalTradeInjector, протокол, timers, init — побайтово не изменены (исключение внутри TradeService: только парное обновление двух UI-счётчиков).

## Проверки
- Node --check исходного и оптимизированного файлов: успешно.
- Проверка разрешённой области изменений: успешно.
- 64 сравнения исходной/новой отрисовки в локальном headless Chromium с jQuery 3.6.0 из проекта.
- Сценарии: рынок/друзья; списки 0/1/10/250 строк; доступно 0/1/3/11 слотов; 0/2 выбранных строк; строки не того режима для проверки исходной фильтрации.
- Совпадают DOM, порядок и индексы строк, подписи, состояния checked/disabled, делегированные click-события, результат refreshSlotUI.
- На парное обновление рыночных счётчиков: чтений capacity 2 -> 1. Вставок готовых строк в живой DOM: N -> 1 (пустой список 0 -> 0).
- Это сравнение поведения UI в Chromium с заглушками игровых данных. AIR/SWF/in-game и реальные серверные действия не проверялись. Процент ускорения, FPS и задержки игры не измерялись.
- Дополнительная попытка запустить Acorn/Playwright в текущем окружении была недоступна: пакеты не найдены. Поэтому отдельную ES5-проверку Acorn не заявляем. Новые конструкции ограничены существующими var/Array/join/if и аргументами функций. DOM-тест выполнен через Chromium CLI.

## Стабильность: найденные риски, НЕ исправленные в этом проходе
- Штатный reload удаляет script-теги, но исходный скрипт не имеет dispose для уже работающих таймеров/очередей. Это требует отдельного исправления жизненного цикла с настоящей AIR-проверкой. В этом проходе запуск/остановка очереди не менялись.
- В исходном коде очередь не ждёт подтверждения сервера, а LocalTradeInjector дополняет данные клиента предварительными сделками. Сохранено, поскольку пользователь запретил менять функционал. Уведомление об отправке не гарантирует приём сервером.
- Начальная очистка удаляет modal DOM непосредственно; быстрое reload открытого окна может конфликтовать с core stage swap/Bootstrap transitions. Не трогали без воспроизведения в рабочем клиенте.
- Исходный handleSortTrades разрешает nextIndex после удаления строки; возможна ошибочная перестановка при перетаскивании. В этом проходе сортировка не менялась.
- Частота отправки 3000ms, cooldown 3000ms, polling слотов 1500ms, TTL pending 90000ms, настройки и шаблоны сохранены.
- Кнопка Stop не добавлялась.

## Ручная приёмка и откат
Перед заменой рабочей копии в tso_portable сохранить её отдельно вне userscripts; не копировать резервные .js в этот каталог, иначе они тоже загрузятся.
Проверить в клиенте пустой/большой список, оба режима, выбор строк и значения слотов 0/1/много. Реальную торговлю для UI-проверки запускать не нужно.
Для отката используется original.js в папке этого отчёта. Настройки и core не менялись. Эта версия НЕ устраняет все перечисленные риски стабильности; она сохраняет текущий функционал и минимально уменьшает повторную работу UI.
