## Исправлено
1. Высокий риск: ранее очереди TimedQueue и таймеры продолжали работать после удаления script-тега/reload. Теперь dispose, учёт таймеров, защита поздних callbacks, повторная регистрация Tools при reload.
2. Высокий риск: несколько параллельных очередей могли повторно занимать одни слоты/тратить одни ресурсы. Добавлен единый lock, замороженная копия сделок и зоны, Stop, остановка при ошибке/смене зоны, отсутствие автоматических повторов. Отправленные запросы отменить невозможно.
3. Высокий риск: LocalTradeInjector писал вымышленные сделки в mTradeData, хотя подтверждения сервера не было. Удалён вместе с неиспользуемой обёрткой TradeQueue. Локальный pending остаётся только предварительным счётчиком с прежним TTL; он не подтверждает приём сделки.
4. Резервирование суммарного offer по ресурсам, учёт количества лотов для баффов. Для баффов проверка консервативная: один подходящий стек должен покрыть накопленный объём; объединение стеков не предполагается. Проверки positive integer и диапазонов для отправки.
5. Удаление видимого основного окна могло нарушить Bootstrap/stage swap/backdrop. dispose сохраняет core handlers до hidden; при show-transition ждёт shown. Повторное открытие ждёт завершения собственного hide/retire; ожидание ограничено. Открытое основное окно больше не пересоздаётся повторным нажатием Tools.
6. Таймер слотов останавливается при закрытии окна, не работает в фоне только ради pending. Один snapshot remaining используется для двух счётчиков; уменьшены повторные bridge-обходы.
7. TimedQueue tick опрашивал часы каждые 50 мс. Локальная очередь использует один отменяемый timeout на следующий шаг. Интервал отправки сохранён: 3000 мс. Реальный AIR может задерживать таймеры, ускорения сервера не обещаем.
8. Отрисовка торговых строк через DocumentFragment вместо append каждой строки в живой DOM. Имена берутся из каталога, экранируются title/имена/значения/имя шаблона.
9. Плитки: pending icons выбираются из сохранённых узлов видимых плиток, а не новым полным jQuery DOM scan. Выбор использует индекс name -> tile вместо filter всех плиток. Typed cache не возвращает иконку другого типа.
10. Исправлена сортировка drag-and-drop: объект следующей строки разрешается ДО splice, иначе индекс после удаления указывал уже на другую строку.
11. Собственные DOM-обработчики получили namespace stTrader / stTraderDropdown; не затронуты core handlers.

## Оставшиеся ограничения / следующий этап
- SEND_TRADE (1049) не имеет обработчика подтверждения в этом скрипте. Статус теперь честно «отправлено, без подтверждения сервера». При timeout/ошибке сверять реальную торговлю, не отправлять повторно вслепую.
- Pending TTL 90s и интерпретация getNextFreeSlotForType сохранены; нужна проверка на реальном SWF. Пока dp пуст, isTradesReady() по-прежнему false: пустой рынок и неготовые данные не различаются.
- Списки друзей/каталог кэшируются в рамках экземпляра. Изменения друзей/событий без reload могут отражаться не сразу. Это не менялось без подтверждённых событий инвалидации.
- Нельзя обещать готовность серверных данных сразу после refresh. Серверное подтверждение и обработка отрицательных ответов требуют отдельного проверенного контракта.
- Стоимость платных coin slots, состояние ресурсов между подготовкой и отправкой и пригодность конкретных VO проверяются сервером; протокол/правила оплаты не изменялись. Суммарная проверка предложения не резервирует игровой инвентарь на сервере.
- Общая обработка коллизий имён складских ресурсов и приключений, кроме Gunpowder, в stock всё ещё использует исходный специальный случай; расширять после проверки каталога.
- Fallback HTML иконок может оставаться закэшированным после поздней загрузки ассетов; фактические missing-icon сценарии проверить вручную.
- Тексты аварийной остановки на английском, уведомление «отправлено» на русском; полная ru/en локализация — отдельный проход.
- Нет live performance benchmark: доказаны устранённые повторные операции, но процент ускорения не измерен.

## Ручная приёмка
1. Cold start, окно, picker, поиск, выбор/подтверждение, ru/en, пустой/большой инвентарь, отсутствующая иконка.
2. 3 последовательных reload: меню одно, таймеры не размножаются.
3. Закрытие/повторное открытие, быстрый reload во время show/hide перехода: нет второго stage swap, лишнего backdrop/пропавших окон.
4. Перетаскивание строк вниз/вверх/в конец, сохранение/загрузка шаблона, classic/rich mode.
5. Stop доступен кнопкой в footer или ShortcutTrader.stop(); он отменяет только ещё не отправленные шаги. disable в manager не вызывает dispose автоматически; сначала Stop или перезапуск клиента.
6. Реальную отправку проверять только по отдельному разрешению: одна дешёвая сделка, ответ/отказ, недостаток ресурсов, ограничение слотов, смена зоны, offline/error. Не путать отправку и подтверждение.
